# Fedfe Buffet

เว็บแอปบุฟเฟ่ต์สำหรับโครงการวิชา Web Development ใช้ PHP, JavaScript, CSS และ MariaDB/MySQL บน XAMPP ลูกค้าสั่งอาหารผ่านหมายเลขโต๊ะโดยไม่ต้องสมัครสมาชิก หน้าลูกค้าแยกเมนู ตะกร้า และรายการที่สั่งออกจากกัน ใช้สีขาวและน้ำเงิน ส่วนพนักงานเปิดโต๊ะ ดูออร์เดอร์ และปิดบิล ผู้จัดการจัดการเมนู บัญชีพนักงาน และดูตารางยอดขายรายวัน

## ติดตั้งใน XAMPP

1. วางโฟลเดอร์โครงการที่ `C:\xampp\htdocs\fedfebuffet`
2. เปิด Apache และ MySQL ใน XAMPP Control Panel
3. สำหรับเครื่องที่ยังไม่เคยติดตั้ง เปิด [phpMyAdmin](http://localhost/phpmyadmin/) แล้ว Import ไฟล์ `database/fedfebuffet.sql` เพียงครั้งเดียว ไฟล์สร้างและเลือกฐานข้อมูล `fedfebuffet` ให้เอง เครื่องปัจจุบันติดตั้งแล้ว จึงไม่ต้อง Import ซ้ำ
4. การเชื่อมต่ออยู่ใน `connection.php`: host `localhost`, ฐานข้อมูล `fedfebuffet`, ผู้ใช้ `root`, รหัสผ่านว่าง และ charset `utf8mb4`
5. เปิด [หน้าเข้าสู่ระบบพนักงาน](http://localhost/fedfebuffet/login.php)

ไฟล์ SQL ไม่ลบหรือแทนที่ฐานข้อมูลเดิม และไม่แก้ไขฐานข้อมูล `buffet` ที่มีอยู่แล้ว หาก `fedfebuffet` มีข้อมูลอยู่ อย่า Import ซ้ำทับงานปัจจุบัน

## บัญชีทดลอง

บัญชีจากไฟล์ติดตั้งใหม่ใช้รหัสผ่าน `FedfeDemo2026!` รหัสผ่านบนเครื่องปัจจุบันอาจถูกเปลี่ยนแล้ว ระบบไม่ได้เปลี่ยนรหัสผ่านเดิมระหว่างการปรับปรุง

| ชื่อผู้ใช้ | สิทธิ์ | สถานะ |
|---|---|---|
| `manager` | ผู้จัดการ | เข้าใช้งานได้ |
| `staff` | พนักงาน | เข้าใช้งานได้ |

รหัสผ่านเก็บเป็น hash ด้วยกลไกมาตรฐานของ PHP ไม่เก็บรหัสผ่านจริงในตาราง ระบบมีสองสิทธิ์คือพนักงาน (STAFF) และผู้จัดการ (MANAGER)

## ทดลองขั้นตอนหลัก

1. เข้าสู่ระบบด้วย `staff` หรือ `manager` เปิดหน้าจัดการโต๊ะ แล้วเลือกโต๊ะที่ปิดอยู่และระบุลูกค้า 2 ท่าน การเปิดโต๊ะอัปเดตหน้าจอโดยไม่โหลดทั้งหน้า อย่าเปิดหรือปิดโต๊ะที่ผู้อื่นกำลังใช้เพื่อทดลองระบบ
2. เปิดลิงก์หน้าลูกค้าของโต๊ะนั้น เช่น [โต๊ะ 1](http://localhost/fedfebuffet/?table=1) ใช้ปุ่ม `− / +` ข้างอาหารเพื่อเลือกจำนวน ลดเหลือศูนย์เพื่อนำออก
3. เปิดหน้าตะกร้าจากแถบนำทาง ตรวจจำนวนและราคาเพิ่ม ใส่หมายเหตุเฉพาะรายการที่ต้องการ แล้วกลับไปเลือกอาหารต่อได้ รายการที่เลือกยังอยู่เมื่อเปลี่ยนหน้า รีเฟรช หรือเรียกพนักงานในรอบเดิม
4. สำหรับตัวอย่างบิล เลือกอาหารรวมในบุฟเฟ่ต์และไอศกรีมวานิลลา 2 ที่ จากนั้นยืนยันส่งออร์เดอร์ในหน้าตะกร้า
5. เปิดหน้ารายการที่สั่งของลูกค้าและคิวออร์เดอร์พนักงาน เปลี่ยนออร์เดอร์เป็นเสิร์ฟแล้ว สถานะอัปเดตประมาณทุก 5 วินาที
6. ทดลองสั่งบิงซูผลไม้รวม 1 ที่ แล้วให้พนักงานยกเลิกทั้งออร์เดอร์นั้น ทดลองเรียกพนักงานจากหน้ารายการที่สั่ง และให้พนักงานกดรับทราบ
7. ลูกค้าขอเช็คบิลจากหน้ารายการที่สั่ง หากยังมีอาหารในตะกร้าต้องจัดการก่อน เมื่อขอแล้วสั่งเพิ่มไม่ได้ พนักงานยกเลิกคำขอที่ผิดพลาดเพื่อกลับมาสั่งต่อได้
8. พนักงานเสิร์ฟหรือยกเลิกออร์เดอร์ที่ยังเตรียมให้ครบก่อนรับชำระ บิลตัวอย่างต้องเป็น `2 × 299 + 2 × 20 = 638 บาท` บิงซูที่ยกเลิกไม่นับเงิน ถ้ายอดเปลี่ยนจากที่ตรวจไว้ ระบบต้องให้ตรวจบิลใหม่ก่อนยืนยัน
9. ยืนยันรับชำระและปิดโต๊ะ การเปิดโต๊ะเดิมใหม่เป็นคนละรอบ ออร์เดอร์และตะกร้าของกลุ่มเดิมไม่ย้ายมารวม หน้ารายการเดิมยังแสดงสถานะจบรอบโดยไม่รับออร์เดอร์ใหม่
10. ใช้บัญชีผู้จัดการทดลองเพิ่ม/แก้ไข/ลบอาหาร เพิ่ม/แก้ไข/ลบบัญชีพนักงาน และดูยอดขายรายวัน หากกรอกไม่ผ่าน ระบบเก็บค่าที่ไม่ใช่รหัสผ่านไว้ให้แก้ไข

ในการติดตั้งใหม่ทุกโต๊ะเริ่มต้นเป็นสถานะปิด ต้องเปิดจากฝั่งพนักงานก่อน การใช้งานจริงอาจมีโต๊ะเปิดและมีข้อมูลลูกค้าอยู่แล้ว จึงไม่ควรล้างข้อมูลเพื่อให้ตรงกับตัวอย่าง ลูกค้าไม่มีสิทธิ์เปิดโต๊ะเอง ไม่มีระบบ QR หรือบัญชีลูกค้า

## กติกาที่ใช้ในระบบ

- บุฟเฟ่ต์ราคา 299 บาทต่อท่าน เก็บราคาของรอบนั้นไว้ตอนเปิดโต๊ะ
- มี 43 เมนูใน 9 หมวด เมนูส่วนใหญ่รวมในบุฟเฟ่ต์ มีของหวานคิดเพิ่ม 6 เมนู
- ทั้งหน้าลูกค้าและหน้าจัดการอาหารเรียงหมวดเป็น เนื้อ → หมู → ไก่ → ทะเล → ผักและเห็ด → เส้นและข้าว → น้ำซุปและน้ำจิ้ม → ของหวาน → เครื่องดื่ม ภายในหมวดเรียงตาม ID หมวดใหม่อื่น ๆ อยู่ท้ายรายการ
- ไอศกรีมวานิลลา/ช็อกโกแลต/สตรอว์เบอร์รี 20 บาท, ไอศกรีมชาเขียว 25 บาท, บิงซูผลไม้รวม 89 บาท และโมจิไอศกรีม 3 ชิ้น 45 บาท
- ออร์เดอร์หนึ่งรายการหมายถึงชุดอาหารที่กดยืนยันพร้อมกัน เปลี่ยนสถานะทั้งชุดได้จากกำลังเตรียมเป็นเสิร์ฟแล้วหรือยกเลิก ผู้จัดการแก้สถานะที่กดผิดโดยคืนเป็นรอจัดเตรียม แล้วเลือกสถานะใหม่ได้เฉพาะรอบที่ยังไม่ปิดบิล
- ยอดรวมคือจำนวนท่านคูณราคาบุฟเฟ่ต์ บวกค่าอาหารเพิ่มเฉพาะออร์เดอร์ที่เสิร์ฟแล้ว
- `ITEM.price` เป็นยอดรวมของรายการที่คำนวณตอนสั่งแล้ว ห้ามนำไปคูณจำนวนซ้ำ การแก้ราคาเมนูไม่เปลี่ยนเงินที่บันทึกไว้ก่อนหน้า
- อาหารหมดชั่วคราวยังแสดง แต่สั่งไม่ได้ อาหารที่ลบจะซ่อนโดยใช้ `is_deleted` เพื่อรักษาประวัติ
- การลบบัญชีพนักงานใช้ SQL `DELETE` จริง ผู้จัดการลบบัญชีอื่นได้หลังยืนยัน แต่ลบบัญชีที่กำลังใช้งานอยู่ไม่ได้
- โต๊ะที่เปิดใช้งานมี 1–9 เท่านั้น รายการโต๊ะ 10 เก็บไว้เฉพาะประวัติเดิม ไม่แสดงในหน้าปฏิบัติงานและไม่รับออร์เดอร์ใหม่
- ตะกร้าเก็บใน PHP session ของเบราว์เซอร์ แยกตามรหัสรอบโต๊ะ จึงคงอยู่เมื่อเปลี่ยนหน้า รีเฟรช หรือเรียกพนักงาน เบราว์เซอร์/อุปกรณ์คนละตัวมีตะกร้าคนละชุด ส่วนแท็บในเบราว์เซอร์เดียวกันที่เปิดรอบเดียวกันใช้ตะกร้าชุดเดียวกัน ออร์เดอร์ที่ส่งแล้วเก็บในฐานข้อมูลและมองเห็นร่วมกันในโต๊ะ
- เมื่อราคาอาหารเปลี่ยนหลังจากลูกค้าเห็นราคา ต้องให้ตรวจราคาใหม่ก่อนส่งสำเร็จ ราคาสุดท้ายตรวจจากฐานข้อมูลเสมอ
- วันที่/เวลาของแอปใช้ `Asia/Bangkok`

ข้อมูลเริ่มต้นมีรอบที่ปิดแล้ว 3 รอบสำหรับตัวอย่างรายงาน: 3 พฤศจิกายน 2026 ยอด 638 บาท, 4 พฤศจิกายน ยอด 986 บาท และ 5 พฤศจิกายน ยอด 1,241 บาท รวม 2,865 บาท ไม่มีส่วนลดในข้อมูลชุดนี้

## รูปภาพ

รูปอาหารใช้เลข ID ของเมนูเป็นชื่อไฟล์ เช่น `images/menu/1.jpg` ผู้จัดการเลือกรูป JPG ขนาดไม่เกิน 2 MB แล้วกดบันทึกเพื่อเพิ่มหรือเปลี่ยนรูป หน้าแก้ไขแสดงรูปปัจจุบัน หากไม่เลือกไฟล์ ระบบใช้รูปเดิม

หน้าเว็บสร้างตำแหน่งรูปจาก ID ของเมนูและเติม `BASE_URL` ด้านหน้า ภาพที่ยังไม่มีหรือโหลดไม่ได้ใช้ `images/placeholder.svg` แทน

สำหรับ InfinityFree ให้อัปโหลดรูป `1.jpg` ถึง `43.jpg` ไปที่ `images/menu/` และใช้ `BASE_URL` เป็น `''` ใน `functions.php` ไฟล์ส่งออกสำหรับโฮสต์ใช้ชื่อตารางตัวพิมพ์ใหญ่ตามคำสั่ง PHP ให้นำเข้าในฐานข้อมูลว่างที่เลือกไว้ใน phpMyAdmin

## โครงสร้างไฟล์และการทำงาน

| ตำแหน่ง | หน้าที่ |
|---|---|
| `index.php` | เมนูอาหารและปุ่มเพิ่ม/ลดจำนวน |
| `cart.php` | ตรวจตะกร้า ปรับจำนวน ใส่หมายเหตุ และยืนยันส่ง |
| `orders.php` | รายการที่ส่งแล้ว สถานะ เรียกพนักงาน และขอเช็คบิล |
| `login.php`, `logout.php` | เข้าสู่ระบบและออกจากระบบพนักงาน |
| `connection.php` | เชื่อมต่อฐานข้อมูลด้วย PDO |
| `functions.php` | ฟังก์ชันร่วมขนาดเล็ก เช่น ตรวจข้อมูลและคำนวณเงิน |
| `includes/` | ตรวจสิทธิ์และส่วนหัว/ท้าย HTML |
| `staff/` | หน้าโต๊ะ ออร์เดอร์ บิล เมนู บัญชี และรายงาน |
| `actions/` | ตรวจ POST แล้วบันทึก ก่อน redirect กลับหน้า |
| `ajax/` | ส่ง HTML สถานะให้ XMLHttpRequest |
| `css/`, `script/` | CSS และ JavaScript แยกจากหน้า PHP |
| `database/fedfebuffet.sql` | โครงสร้าง 8 ตารางและข้อมูลทดลองขนาดเล็ก |
| `docs/` | แบบร่างหน้าจอ แผนภาพระบบ และแผนภาพฐานข้อมูล |

การทำงานปกติคือ `หน้า PHP → form POST → actions → prepared SQL → redirect` ส่วนข้อมูลสถานะใช้ `XMLHttpRequest → ajax → HTML responseText` ไม่มี JSON endpoint

ไฟล์ติดตั้งตัวอย่างเดิมคง `MEMBER` และ `SESSION_MEMBER` ตามโครงสร้างที่ออกแบบ ไฟล์ส่งออกสำหรับโฮสต์มีเฉพาะหกตารางที่ระบบใช้งาน และใช้ ID เมนูระบุตำแหน่งรูปโดยตรง

## Cookie และ session แบบสั้น

PHP session เก็บรหัสพนักงานที่เข้าสู่ระบบไว้ฝั่งเซิร์ฟเวอร์ ส่วนเบราว์เซอร์เก็บ cookie ที่มี session ID เพื่อให้คำขอถัดไปรู้ว่าเป็นพนักงานคนเดิม เมื่อออกจากระบบจึงล้างข้อมูล session และ cookie ไม่ต้องสร้างระบบจำรหัสผ่านเอง

ลูกค้าไม่ต้องเข้าสู่ระบบ ใช้หมายเลขโต๊ะและรหัสรอบที่ตรวจสอบกับฐานข้อมูล PHP session แบบไม่ระบุตัวตนเก็บตะกร้าแยกตามรอบ รวมทั้ง token ของแบบฟอร์มและการป้องกันส่งซ้ำ ไม่ได้ใช้ session จำโต๊ะเดียวครอบทุกหน้า และไม่ได้นำอาหารที่ยังไม่ส่งไปเขียนเป็นออร์เดอร์ในฐานข้อมูล

ตาราง `SESSION` ในฐานข้อมูลหมายถึงรอบการรับประทานอาหารของกลุ่มลูกค้า ซึ่งเป็นคนละอย่างกับ PHP session

## ขอบเขตและเกณฑ์วิชา

เวอร์ชันนี้ไม่ทำสมาชิก คะแนนสะสม โปรโมชั่นทุกชนิด นำเข้าเมนู JSON กราฟ dashboard ระบบจอง หรือชำระเงินออนไลน์ เกณฑ์พื้นฐานข้อ 7 เรื่อง JSON จงใจเว้นตามขอบเขตที่ตกลงกัน

| ข้อ | หลักฐานในโครงการ |
|---|---|
| 1 | `docs/wireframes.html` และ `docs/system-architecture.mmd` |
| 2 | CSS selector หลายชนิดใน stylesheet |
| 3 | HTML form validation ของข้อมูลที่ใช้งานจริง |
| 4 | HTML semantic layout |
| 5 | CSS media queries สำหรับหลายขนาดหน้าจอ |
| 6 | การเปลี่ยน style ผ่าน DOM ในหน้าลูกค้า |
| 7 | เว้น JSON |
| 8 | PDO และเมนู CRUD โดยลบแบบรักษาประวัติ |
| 9 | Cookie/PHP session ของการเข้าสู่ระบบพนักงาน |
| 10 | XMLHttpRequest สำหรับสถานะออร์เดอร์และการแจ้งเตือน |
| 11 | ตารางยอดขายรายวันแบบ GROUP BY ไม่มีกราฟ |

ดูรายละเอียดแผนและการตัดสินใจใน `PLAN.md` แผนภาพ `.mmd` เปิดด้วยเครื่องมือที่รองรับ Mermaid ได้ ส่วนแบบร่างหน้าจอเปิดในเบราว์เซอร์ได้โดยตรง

## การตรวจสอบและสถานะการปรับหน้า

เครื่องนี้นำเข้าฐานข้อมูล `fedfebuffet` แล้ว ไม่ต้อง Import ซ้ำ ฐานข้อมูล `buffet` เดิมไม่ได้ถูกแก้ไข ข้อมูลการใช้งานที่เกิดขึ้นหลังการติดตั้งต้องเก็บไว้ รวมถึงโต๊ะที่ผู้ใช้เปิดอยู่

- ตรวจ syntax ของไฟล์ PHP ทุกไฟล์ และ JavaScript ทั้งสองไฟล์แล้ว
- ในรุ่นแรกทดลองผ่าน Chrome จริงครบ เปิดโต๊ะ → เลือกอาหาร → ส่งออร์เดอร์ → อัปเดตสถานะผ่าน Ajax → เช็คบิล → ปิดโต๊ะ → เปิดรอบใหม่
- ตรวจยอด 638 บาท การยกเลิกอาหาร การปฏิเสธส่งออร์เดอร์ซ้ำ อาหารหมด และการสั่งหลังขอเช็คบิล
- ตรวจการเรียก/รับทราบพนักงาน การแยกตะกร้าระหว่างอุปกรณ์ และแท็บเก่าที่ส่งเข้ารอบใหม่ไม่ได้
- ตรวจสิทธิ์พนักงาน/ผู้จัดการ เมนู CRUD และบัญชีพนักงาน รวมทั้งออกจากระบบและ token แบบฟอร์ม
- ตรวจหน้าลูกค้าและหน้าโต๊ะพนักงานขนาดโทรศัพท์/เดสก์ท็อป และดูภาพหน้าจอจริง ไม่มี JavaScript error ระหว่างขั้นตอนทดสอบ
- ข้อมูลตัวอย่างจากไฟล์ติดตั้งมี 3 รอบ ยอดรวม 2,865 บาท และเมนู 43 รายการ จำนวนข้อมูลในระบบปัจจุบันอาจเพิ่มจากการใช้งาน

การทดสอบรุ่นแรกพิสูจน์ว่าธุรกรรมหลักทำงาน แต่ไม่ได้พิสูจน์ว่าขั้นตอนใช้งานสะดวก หลังการตรวจ UX จึงปรับเป็นหน้าขาว/น้ำเงิน 3 หน้าและตะกร้าที่จำรายการ และตรวจขั้นตอนที่ปรับใหม่ผ่าน Chrome แล้วเมื่อวันที่ 5 พฤศจิกายน 2026 ดังนี้:

- เปิดโต๊ะแล้วปรับเฉพาะการ์ด โดยหน้าไม่โหลดใหม่
- กดจำนวนเร็วหลายครั้งแล้วเปลี่ยนหน้า รายการและหมายเหตุยังอยู่ รวมถึงหลังรีเฟรชและเรียกพนักงาน
- ตะกร้าของเบราว์เซอร์อื่นแยกจากกัน และการแก้ในอีกแท็บของเบราว์เซอร์เดียวกันต้องตรวจทานก่อนส่ง
- จำลองการบันทึกล้มเหลว มีปุ่มลองบันทึกอีกครั้ง และป้องกันออกจากหน้าขณะที่ยังบันทึกไม่สำเร็จ
- จำนวนไม่ถูกต้องส่งออร์เดอร์ไม่ได้; นำอาหารสุดท้ายออกแล้วแสดงตะกร้าว่าง
- อาหารหมดระบุชื่อรายการให้แก้ไข; ราคาเปลี่ยนต้องตรวจทานใหม่; ส่งซ้ำไม่สร้างออร์เดอร์เพิ่ม
- สถานะเสิร์ฟอัปเดตจริง ผู้จัดการแก้สถานะผิดได้ก่อนชำระเงิน พนักงานยกเลิกคำขอบิลแล้วลูกค้าสั่งต่อได้
- บิลตัวอย่างยังเท่ากับ 638 บาท และยอดที่เปลี่ยนหลังเปิดหน้าบิลไม่ถูกยืนยันเงียบ ๆ
- ประวัติออร์เดอร์ยังอยู่หลังปิดรอบ; แบบฟอร์มพนักงานที่ข้อมูลซ้ำไม่ล้างข้อมูลที่กรอกไว้ และไม่เก็บรหัสผ่าน
- การแจ้งสถานะโต๊ะเก่าไม่เขียนทับจำนวนลูกค้าที่กำลังกรอก; คำขอ Ajax ที่ไม่ได้เข้าสู่ระบบได้สถานะ 401
- ดูภาพจริงของเมนู ตะกร้า และรายการที่สั่งบนโทรศัพท์/เดสก์ท็อป ตรวจปุ่มจำนวนขนาด 44px ให้ไม่ถูกตัดที่ความกว้าง 320, 390, 768 และ 1280px

ตรวจ syntax ผ่านทั้ง 27 ไฟล์ PHP และ JavaScript ทั้งสองไฟล์ ตรวจคำสั่งทดสอบบิลด้านล่างผ่าน ไม่มี JavaScript error ระหว่างขั้นตอนทดสอบ ข้อมูลที่สร้างเพื่อการตรวจถูกลบเฉพาะรอบ 21–23 ของโต๊ะ 10 และอาหารทดสอบ 45 ส่วนข้อมูลการใช้งานจริงอื่นไม่ได้ถูกล้าง ดูรายละเอียดการตรวจ UX ใน `UX_AUDIT.md`

ทดสอบกฎคำนวณบิลเมื่อมีโต๊ะ 1–9 อย่างน้อยหนึ่งโต๊ะปิดอยู่ โดยรันจากโฟลเดอร์โปรเจกต์ ไม่ต้องติดตั้งเครื่องมือเพิ่ม:

```powershell
Set-Location 'C:\xampp\htdocs\fedfebuffet'
& 'C:\xampp\php\php.exe' 'tests\smoke.php'
```

สคริปต์เลือกโต๊ะที่ปิดอยู่ภายใน 1–9 แล้วตรวจการนับตะกร้า ราคา ณ เวลาสั่ง การไม่นับออร์เดอร์ยกเลิก/ยังไม่เสิร์ฟ และรอบบริการ จากนั้น rollback ข้อมูลทดสอบทั้งหมด ไม่ปิดหรือแก้โต๊ะที่กำลังให้บริการ เลข ID อาจมีช่วงที่ข้ามได้ตามปกติของ AUTO_INCREMENT

## โครงสร้างหน้าจอและผลตรวจล่าสุด

หน้าใช้งานทั้ง 10 หน้ามี `<!DOCTYPE html>`, `<html lang="th">`, `<head>`, CSS, deferred script, `<body>` และแท็กปิดครบในไฟล์นั้นเอง ใช้ `require_once "connection.php";` สำหรับหน้าหลัก และ `require_once "../connection.php";` สำหรับหน้าพนักงาน ไม่มี `__DIR__` ในโค้ด PHP ตัวแปรหน้าจอประกาศตรงส่วนบนของแต่ละหน้า ส่วนไฟล์ร่วมเป็นฟังก์ชันขนาดเล็กที่รับข้อมูลอย่างชัดเจน

เมนูแสดงเป็นหมวดพร้อมหัวข้อ ตัวกรองเลือกซ่อนหรือแสดงทั้งหมวด อาหารฟรีไม่แสดงข้อความราคา อาหารคิดเพิ่มแสดงราคาต่อที่ ปุ่มเพิ่มรายการใช้ไอคอนบวกและปุ่มแจ้งหมดใช้คำว่า “หมด” หน้าโต๊ะเข้าไม่ได้แสดงไอคอนและข้อความตรงกลางโดยไม่มีทางเข้าพนักงาน

ตรวจผ่าน Chrome ทั้ง 11 สถานการณ์หน้าจอที่ความกว้าง 390, 768 และ 1440px รวม 33 ภาพ ตรวจกลุ่มอาหาร ตะกร้า/หมายเหตุ การเปิดโต๊ะ 9 ใบ การลบบัญชีจริงและการปฏิเสธลบบัญชีตัวเอง การสิ้นสิทธิ์ของบัญชีที่ลบ และบิล 638 บาท ข้อมูลทดสอบและบัญชีชั่วคราวถูกนำออกหลังตรวจ โดยไม่เปลี่ยนบัญชีและรหัสผ่านเดิม

ผลตรวจ Intelephense 1.18.5 แบบสร้างดัชนีใหม่กับ PHP 8.2.12: 27 ไฟล์, **0 errors, 0 warnings, 0 informational diagnostics** ไม่มีการปิดการแจ้งเตือนเพื่อซ่อนปัญหา ตรวจ PHP syntax และ JavaScript ผ่าน และไม่มี JavaScript exception หรือ console error ในขั้นตอนทดสอบ

โค้ดใช้ PHP แบบ procedural, PDO, `while` และ `for` ปกติ ไม่มี PHP `foreach` หรือ JavaScript `.forEach()` และไม่มีระบบ build/dependency ของแอป
